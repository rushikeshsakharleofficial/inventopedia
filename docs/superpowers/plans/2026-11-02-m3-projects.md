# M3 Projects Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task-by-task. Steps use checkbox syntax.

**Goal:** Ship authenticated project CRUD and organisation subscription usage with atomic quotas.
**Architecture:** Reuse M2 middleware and caller-scoped Supabase clients. Creation uses a service-only PostgreSQL transaction with actor authorization and a subscription row lock.
**Tech Stack:** Hono, TypeScript strict, Zod, Supabase PostgreSQL, Vitest/PGlite.
**Spec:** docs/superpowers/specs/2026-11-02-m3-projects-design.md (approved 2026-11-02).

## Global constraints

Work on main per AGENTS.md; preserve local documentation. Free 2, Starter 5,
Business 10, Enterprise custom/null. No billing, UI, membership endpoints, hosted
migrations or deployments. All schema changes in migration 004. No new infra.

## Review focus

- Revoked org administrator cannot use privileged creation even after an HTTP scope check.
- Missing subscription must fail closed; unexpected DB errors must not become quota errors.
- Arbitrary UUID/cursor text cannot become PostgREST filter syntax.
- Subscription usage must count all org projects, including ones invisible to ordinary members.
- Tier/limit mismatches and negative limits must not bypass the subscription contract.
